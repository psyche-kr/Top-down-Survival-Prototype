# 작업지침서

이 프로젝트에서 작업할 때 지키는 규칙입니다. 새 규칙이 생기면 여기에 추가합니다.

## 기획 기준

- 이터널 리턴(Eternal Return)의 UI와 시스템을 참고합니다.
- 기능을 만들기 전에 **최신에 가까운** 이터널 리턴 자료(공식 패치노트, 플레이 영상, 공략글, 스크린샷)를 찾아보고 그 기준으로 구현합니다. 오래된 자료는 UI와 기획이 달라서 쓰지 않습니다.
- 사용자가 준 스크린샷이 있으면 그것을 1순위 기준으로 삼습니다.
- 모호한 기획(수치, 데이터, 표시 문구, 동작 방식)은 마음대로 정하지 않고 먼저 논의합니다.
- 이터널 리턴의 캐릭터·아트·이름을 그대로 가져오지 않습니다. 구조와 사용성만 참고합니다.

## 작업 흐름

1. 요청과 참고 이미지 확인
2. 최신 이터널 리턴 자료 조사
3. 정해지지 않은 부분 논의
4. 구현 (Unity MCP로 씬/프리팹 작업 포함)
5. 플레이 모드에서 확인 (캡처)
6. [개발일지](DEVLOG.md)와 README 갱신

## 코드 구조 원칙

- 스크립트는 `Assets/2. Scripts` 아래 기능별 폴더에 둡니다 (Character, Chest, Inventory, Item, UI, Input, Interface 등).
- 입력은 `GameInput`(Input System)에서만 정의하고 다른 스크립트는 액션만 읽습니다.
- 아이템·상자 같은 데이터는 `ScriptableObject`로 관리합니다.
- 월드 상호작용은 `IInteractable`, 마우스 오버 강조는 `IHoverable` 인터페이스로 붙입니다.
- 오브젝트·유닛 강조는 `ObjectOutline`의 `HighlightType`으로 구분합니다. 오브젝트는 평소 하얀 테두리 + 호버 하늘색(가려져도 보임), 적은 호버 빨강, 아군은 호버 파랑입니다.
- 유닛 표시 정보(닉네임, 레벨, 체력, 나/아군/적)는 `UnitProfile`에 두고, 머리 위 UI는 `OverheadUI` 프리팹으로 자동 생성합니다.
- 인벤토리 데이터는 칸 위치가 고정된 10칸이며, 데이터는 드롭이 확정되는 순간에만 바꿉니다.
- 아직 시스템이 없는 UI(스탯, 스킬, 장비 등)는 자리만 만들고, 연결할 지점(`PlayerHUD` 등)을 남겨 둡니다.
- UI 칸(슬롯)처럼 마우스를 받아야 하는 요소는 루트 Graphic의 `raycastTarget`을 켜고, 장식용 자식(아이콘, 번호, 배경)은 끕니다.
- TMP 폰트(Rix X ladywatermelon)는 SDF 여백이 1이라 머티리얼 외곽선(`_OutlineWidth`)·두께(`_FaceDilate`)를 0으로 둡니다. 텍스트별로 외곽선을 켜면 글자 뒤에 박스가 생깁니다.
- 월드 대상을 따라다니는 화면 UI(머리 위 HP바, 바닥 아이템 이름표)는 `WorldUILayer.Get()` 아래에 만듭니다. 패널(상자 창, HUD, 툴팁)보다 항상 아래, 3D 오브젝트보다는 위에 보입니다.
- 씬·프리팹 변경은 편집 모드에서 하고 저장합니다. 플레이 모드 중 바꾼 것은 종료하면 사라집니다(더미 모델이 빠졌던 원인).
- 드래그 중 원본 UI가 다시 만들어질 수 있으므로, 드래그 상태는 `ItemDragManager`가 스스로 정리합니다(놓기는 `OnEndDrag`, 놓치면 `LateUpdate`에서 `CancelDrag`).
- 유닛 모델은 유닛 오브젝트의 자식 `Model`로 둡니다(키 1.71m, 캡슐 콜라이더·NavMeshAgent 높이도 같게. 머리 위 UI는 머리끝에서 약 1.45m 위). 카메라는 각도 65도, FOV 40, 거리 약 18m. 이동은 NavMeshAgent, 애니메이션은 `CharacterAnimator` + `CharacterLocomotion` 컨트롤러(제자리 클립, 루트 모션 끔)로 처리해 모델만 바꿔 끼울 수 있게 합니다.
- 애니메이션 속도는 `CharacterAnimator`가 모델 크기로 자동 계산합니다(`Gait` 0 대기·1 걷기·2 달리기). 이동 속도나 모델 크기를 바꿔도 발이 미끄러지지 않으니 블렌드 기준값을 손으로 맞추지 않습니다.
- 지형·오브젝트를 배치하거나 옮기면 NavMesh Surface를 다시 굽습니다. 유닛에는 `NavMeshModifier`(Ignore From Build)를 붙여 굽기에서 빼고, 상자 같은 장애물에는 `NavMeshModifier`(Override Area → Not Walkable)를 붙여 표면에 NavMesh 조각이 생기지 않게 합니다.
- 월드 크기(아이템 아이콘, 간격, 이름표 높이)는 카메라 거리와 함께 봅니다. 카메라를 옮기면 화면 속 크기가 같도록 같은 비율로 맞춥니다.
- 외부 에셋 머티리얼이 Built-in(Standard)이면 URP Lit으로 변환해서 씁니다.
- 카메라는 `LateUpdate`(실행 순서 -100)에서 움직이고, 카메라 기준으로 화면 좌표를 계산하는 UI(머리 위 UI 등)는 그 뒤(+100)에 실행합니다.
- 화면 전체가 스크롤되는 카메라라서 VSync(PC 품질 단계)와 MSAA를 켜 두고, 바닥처럼 넓게 비스듬히 보이는 텍스처는 Trilinear + 이방성 필터를 씁니다.
- 시간에 따라 변하는 이펙트는 단계별 확인을 위해 `Seek(t)` 같은 시점 이동 함수를 둡니다.
- 멀티플레이는 Netcode for GameObjects 도입 예정이므로, 로컬 입력은 소유자만 읽도록 확장할 수 있게 둡니다.
